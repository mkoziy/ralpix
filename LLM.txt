ralpix devcontainer bootstrap instructions

Use these instructions when setting up a target project to run pi and ralpix inside a devcontainer while keeping the target project's existing Makefile behavior.

Goal

- Run pi and ralpix inside the devcontainer
- Forward bun and docker commands from inside the devcontainer to the host via `pi --host`
- Allow the target project's Makefile to keep using host-oriented commands such as `bun run --cwd ...`, `docker compose ...`, bind mounts, and `localhost` service URLs without rewriting them

Files to copy into the target project

1. Copy `.devcontainer/devcontainer.json` from this repository into the target project's `.devcontainer/devcontainer.json`.
2. Copy `.devcontainer/bin/bun` from this repository into the target project's `.devcontainer/bin/bun`.
3. Copy `.devcontainer/bin/docker` from this repository into the target project's `.devcontainer/bin/docker`.
4. Preserve executable bits on both wrapper scripts.

Expected target project layout

```text
.devcontainer/
├── bin/
│   ├── bun
│   └── docker
└── devcontainer.json
```

Requirements for the copied devcontainer.json

- The workspace must be mounted at `/workspace`.
- `remoteEnv.PATH` must prepend `/workspace/.devcontainer/bin`.
- The container must mount a host auth file to `/home/pi/.pi/agent/auth.json`.
- Prefer an absolute host path for the auth mount source if the devcontainer runner does not reliably expand `${localEnv:HOME}`.
- When preparing the target project, detect the user's home directory on the host and write the auth mount source accordingly, for example `/Users/<user>/.pi/agent/auth.json` on macOS.
- If absolute host home paths are undesirable, create a repo-local symlink such as `.devcontainer/host/pi-auth.json` pointing to the real host auth file and mount that stable repo-local path instead.

Wrapper behavior

- `.devcontainer/bin/bun` must execute: `pi --host bun "$@"`
- `.devcontainer/bin/docker` must execute: `pi --host docker "$@"`

Host preparation

1. Detect the host home directory path.
2. Ensure the host auth file exists:
   `mkdir -p "$HOME/.pi/agent" && touch "$HOME/.pi/agent/auth.json"`
3. Write the auth mount in `.devcontainer/devcontainer.json` using either:
   - the detected absolute host path, or
   - a repo-local symlink path that points at the host auth file
4. Rebuild or reopen the target project in the devcontainer after copying the files.
5. Inside the devcontainer, run `/login` in pi if OAuth auth is needed.

Verification

1. Confirm `bun` resolves to `/workspace/.devcontainer/bin/bun`.
2. Confirm `docker` resolves to `/workspace/.devcontainer/bin/docker`.
3. Run the target project's normal `make` commands from inside the devcontainer.

Important behavior

- `make` may run inside the devcontainer.
- `bun` and `docker compose` invoked by the Makefile should run on the host through the wrapper scripts.
- Do not rewrite project `Makefile` service URLs from `localhost` to `host.docker.internal` for this setup.
- The published `ghcr.io/mkoziy/ralpix` image also restores `/workspace/.devcontainer/bin` from `/etc/profile.d` for login shells, so wrapper resolution survives devcontainer clients that do not apply `remoteEnv`.
